# Review Report

## Severity

- P0: Hard violation that must be fixed, such as raw color outside token layer or reversed Chinese financial red/green semantics.
- P1: Major system consistency issue, such as missing light/dark coverage, Figma/frontend token mismatch, or wrong required component token.
- P1: Financial list generated as a row/card summary when table-list structure is required by fields, headers, filters, fixed columns, or horizontal scrolling.
- P2: Product-design quality issue, such as web-like mobile page structure, nested cards, weak data hierarchy, or poor scan efficiency.
- P3: Suggested improvement that does not block delivery.

## Finding Format

Each finding must include:

- Severity.
- Problem location.
- Violated rule.
- Why the rule exists.
- Current color or current design.
- Expected token or expected rule.
- Suggested fix.
- Rule source file.

## Summary Format

End reviews with:

- Token compliance summary.
- Light/dark coverage summary.
- Financial red/green semantics summary.
- Mobile/page structure summary.
- Component rule summary.
- Open gaps needing user confirmation.
